# v4.0.0 正式盲评分任务模板

## 1. 冻结输入

- 发布包：`anchor-v4-formal-20260828`。
- 锚点：同目录 `anchor_v4_正式发布.md`，按其固定顺序执行。
- 模型：`provider=minimax-cn`，`model=MiniMax-M3`；不得使用 `minimax` provider。
- 当前卡：系统仅挂载本卡的匿名正文（已按发布包规则删除首个物理文本行）、本模板和发布锚点；不得读取其他卡、manifest、标签或项目目录。
- 本任务不接收、不输出标题、作者、商业字段、标题映射或作者映射。

## 3. 正文统计与证据

评分前以当前卡的去首行正文 `text` 执行：

```python
import re
L = len(re.sub(r"\s+", "", text))
K = L / 1000
```

`\s` 使用 Python Unicode 正则语义，移除全部空白码点；标点、全角字符和普通字母保留。证据中的位置使用正文 Unicode 码点/自然段/场景等可复核口径，并保留逐字引文；需要比例或密度时写出原始分子、分母和精确比较。首行剥离不是评分员事后编辑：构建侧删除首个物理文本行及其行终止符，异常材料由构建侧拒绝，不得自行修补。编码、原始长度、`L`、`K`、统计脚本/命令和首行剥离结果只写入构建侧受限 sidecar，并按同目录 `构建侧输入审计.schema.json` 校验；评分 JSONL 不承载这些机器字段，也不读取 sidecar。

## 4. 判定纪律

- 每项只允许 `0`、`5`、`10`。
- 先按锚点列候选对象，再写证据、判定项成立/不成立、计数/算式、分数、排除项和不确定项。
- 相同证据按相同规则必须得到唯一分数；不得用题材常识、作者意图、商业印象、历史结果或其他指标结果补证。
- `evidence` 和 `reason` 必须非空；证据必须来自当前卡正文，不得写入正文外信息。

## 5. 输出契约

输出一行 UTF-8 JSON，且必须通过同目录 `score_record.schema.json`。构建侧另行生成 sidecar，并必须通过同目录 `构建侧输入审计.schema.json`；sidecar 只供构建/审计使用，不挂载给评分 worker：

- 顶层恰好三个键：`id`、`rep`、`scores`；不得增加、删除或改名。
- `scores` 是恰好19项的数组，顺序必须与第2节完全一致。
- 每项恰好四个键：`indicator`、`score`、`evidence`、`reason`；`indicator` 必须是对应的完整 ID+名称。
- 不输出 markdown、解释文字、标题/作者/标签、路径、其他卡信息或历史结果。
- 不在评分 JSONL 中增加编码、原始长度、`L`、`K`、统计脚本/命令或首行剥离字段；这些字段的唯一机器承载位置是构建侧受限 sidecar。
