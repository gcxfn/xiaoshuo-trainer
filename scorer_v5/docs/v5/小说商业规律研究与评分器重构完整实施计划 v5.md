# 小说商业规律研究与评分器重构完整实施计划 v5

## 0. 项目最终目标

项目最终不是为了证明现有 19 个指标正确，而是回答三个彼此独立的问题：

### Q1：这些指标能不能被稳定测量？
同一本小说重复评分，结果是否基本一致。

### Q2：稳定测量出来的指标，能不能预测商业表现？
例如不知道 S/A/B/C 标签时，仅凭文本指标，是否真的能够提高对商业档位的预测能力。

### Q3：具有预测力的指标，主动用于写作后，能不能提高作品质量？
即“爆款作品经常具有某特征”是否能够进一步升级为“主动增加该特征有帮助”。

三关必须按顺序通过：

**测量可靠性 → 预测有效性 → 创作有效性**

任何一关失败，都不能跳到下一关。

# Step 4：逐个拆解 19 个指标

不要先决定谁交给 LLM、谁交给 Python。

逐项问：

### 问题 A
这一步是否能由程序百分百确定？

例如：

- 字符数
- 段落编号
- offset
- 小说总长度 L
- K=L/1000
- 事件数量 N
- F=N/K
- 前10%
- 后15%
- 比例
- 阈值
- 最终 0/5/10 映射

答案如果是 YES：

> 必须交给 Python。

### 问题 B
是否需要理解小说语义？

例如：

- 这是不是有效冲突？
- 是否属于关系升级？
- 是否发生身份反转？
- 两段行为是否属于同一个事件？
- 是否真的形成角色状态改变？
- 行为是否发生在同一场景？

答案如果是 YES：

> 交给 LLM。

### 问题 C
概念是否过于主观？

例如类似：

- 爽不爽
- 强不强
- 精不精彩
- 有不有吸引力

不能直接留着。

必须优先拆成多个可判断条件。

如果仍无法拆：

> 标记为 SUBJECTIVE。

SUBJECTIVE 指标以后必须采用多 Judge，而不能假装是客观测量。

# Step 6：彻底删除 LLM 的最终 `score`

这是 v5 最关键的改变。

旧模式：

```json
{
  "metric": "B01",
  "score": 5,
  "evidence": "...",
  "reason": "..."
}
```

删除。

v5 应该类似：

```json
{
  "metric": "B01",
  "candidate_found": true,
  "candidate_quote": "...",
  "candidate_start_quote": "...",
  "is_external_event": true,
  "same_scene_action": false,
  "action_quote": null
}
```

然后程序计算：

```text
candidate_start
↓
找到真实 offset
↓
q = offset / L
↓
调用 B01.score()
↓
得到最终 0/5/10
```

### 强制原则

**LLM 没有权限输出正式 score。**

这样可以永久消灭：

> reason 写“应该 5 分”，JSON 却填 0 分

这一类错误。

# Step 7：专门重构 N6/B33 类型指标

这两项优先做。

LLM只输出事件：

```json
{
  "events": [
    {
      "event_id": "E1",
      "description": "...",
      "evidence": ["...", "..."],
      "qualifies": true
    }
  ]
}
```

然后进入第二层 verifier：

```text
事件真的存在？
↓
证据匹配？
↓
是否符合定义？
↓
是否和另一个事件重复？
```

最终程序：

```python
N = number_of_verified_unique_events
K = sidecar["K"]
F = N / K
score = metric_rule(F)
```

### 禁止

LLM输出：

```text
K≈6.1
F≈0.66
```

甚至无需把 K 告诉 LLM。

# Step 9：允许 ABSTAIN

当前系统逼模型：

> 一定要给0/5/10。

这很危险。

v5 增加：

```json
{
  "status": "ABSTAIN",
  "reason": "无法从正文可靠判断..."
}
```

使用场景：

- 无法确认事件边界；
- 缺少必要证据；
- 两种解释均合理；
- 输出证据互相冲突。

ABSTAIN 不自动转成 0。

单独统计：

> abstention_rate

如果某指标大量 ABSTAIN，本身就是这个指标不可操作的证据。

# Step 39：匿名随机盲评

评审看到：

> 小说 A / 小说 B

不知道：

随机交换 A/B 顺序。

### C级
多个不同模型独立 judge。

### D级
同一个生成模型自己评价自己。

D 级只能辅助诊断，不能作为核心结论。

# Step 42：创作规则的最终分类

建立：

`writing_rules_registry.yaml`

每条规则记录证据等级。

### Grade A — Causal/Experimental
盲实验表明主动使用有帮助。

可以：

> 强推荐给 Writer Agent。

### Grade B — Predictive
真实作品中能预测商业表现，但尚未证明主动加入有帮助。

只能：

> 作为建议。

### Grade C — Correlational/Hypothesis
只发现相关趋势。

只能：

> 保留研究。

### Grade D — Failed
不稳定/无预测力/实验失败。

> 禁止进入写作提示词。

# 项目成功标准

项目成功绝不能定义为：

> “最后找到了一套规则。”

正确成功定义：

### 成功结果 A
找到若干可靠、预测有效、创作实验有效的规则。

最好。

### 成功结果 B
找到少量预测特征，但主动写入无帮助。

仍然是有效研究结论。

### 成功结果 C
19项大部分或全部被证伪。

依然成功，因为避免以后在错误规则上继续训练和烧 token。

### 真正失败的结果

只有一种：

> 不允许假设死亡，不断修改 prompt、阈值、测试集和标准，直到得到想看的结果。

这个流程必须从 v5 开始彻底禁止。
